# 0.8.0: Complete trace hooks

**0.8.0 gives a host every fact that a trace backend needs.** The journal
records what a room decided. The trace records how a seat got there: each
pass, each model request with its input and output, and each tool call.
Ambion gives these steps to the `TraceLogger` of the host. The app decides
where they go: Phoenix, Langfuse, a file, or nowhere.
[1.0.0](1.0.0.md) holds the road.

**The hooks come first, so every later release is visible.** Today a
logger receives every step in order, with the room, the seat, the
activation, the pass, and the time. Four facts are missing.

**Evidence:**

- A scripted activation records one `input` step for each pass when the
  policy is `full`, and none when the policy is absent or `omit`.
- Each traced step of an activation in an open exchange names the seq of
  the message that opened it. An activation outside an exchange names
  none.
- The executor conformance suite checks, for Pi, Claude, and Codex, one
  `session` step with the model, and one `usage` step for each model
  request.
- `docs/traces.md` states each step, its order, the policy, and the
  limits. A host can build the spans of one activation from the steps
  alone.

## The items

**TR1. The `input` step of the trace.** A pass records the range of the
record that it read. The text that the model received is not recorded, so
a model request shows output with no input.

- `{ type: 'input'; part: 'system' | 'record'; text: string }`, recorded when an executor calls
  `pass.record()`. The driver wraps `record()`, so no executor changes.
- The first pass also records the system part once.
- An optional trace policy field `input: 'omit' | 'full'`. An absent field
  reads as `omit`, so no host changes its `trace` option.
- A limit `limits.trace.inputBytes` of its own. The 64 KiB of
  `toolOutputBytes` would cut a rendered record.
- The step holds no vendor history and no compaction. The vendor session
  keeps those, joined by the `session` id on the ended lease.

**TR2. The exchange on each traced step.** A trace backend groups the
activations of one question. Neither `TracedStep` nor `activation_start`
names the exchange, so a host must guess it from the order of room
events. `TracedStep` gains `exchange?: Seq`, the seq of the message that
opened the exchange that the activation works on. The room knows it when
it wakes the seat.

**TR3. The model on every executor.** Claude and Codex record a `session`
step with the model. Pi records none, so a host cannot name the model of
a Pi request. The Pi executor records one `session` step with the model of
its options at the start of each activation.

**TR4. One usage step for each model request of Claude.** The Claude
executor reports usage once for each SDK result, so a Claude pass with
five requests shows one usage step. The Claude trace splits usage for
each assistant message. Pi reports usage for each request. Codex reports
the usage of each model response from `tokenUsage.last`.

**TR5. The trace contract.** The executor conformance suite asserts the
steps that each executor must record: `session`, one `usage` for each
request, and `input` under the full policy. A page `docs/traces.md` states
the steps, their order, the policy, the limits, and the mapping of the
steps to a span tree. The page names no backend as the default.

## Decisions taken

| Decision                                           | Reason                                                       |
| -------------------------------------------------- | ------------------------------------------------------------ |
| Ambion ships trace hooks and no exporter           | The app owns its observability; Ambion owns the room         |
| The kernel has no OpenTelemetry dependency         | A host that wants OTLP adds it in its own code               |
| The journal stays the source of truth              | A span tree cannot hold who woke whom or the order of record |
| The workbench keeps its trace view in memory       | An exporter in the workbench is a choice of that app         |
| The full trace policy copies secrets to the logger | `docs/traces.md` states it; the host chooses the policy      |

The design of a Phoenix exporter over these hooks is
`observability/phoenix-design.md` in the project files. The review
"Workbench readiness of the 0.7.0 core" of 2026-10-06 places traces
first.
