What this change built

The workspace is shipped. docs/workspace.md was written ahead of the code, and this branch builds what it specifies: defineWorkspace names an identity and data boundary, an agent names it with one optional field, and every activation of that agent holds Pi’s own read, write, edit and bash, bound to an environment the workspace builds fresh on every call. A custom tool reaches the same environment through ctx.workspace(), the second argument every defineTool execute now receives.

just-bash backs it. A virtual Unix filesystem and shell run in-process. One filesystem belongs to the workspace, each connected agent gets a fresh Bash instance over it with cwd at /home/<name>, and bash-env.ts adapts that instance to Pi’s ExecutionEnv: thrown errors classified into Pi’s codes, output delivered through the callbacks before exec resolves, ~ expanded to the agent’s home, an abort told apart from a timeout. The in-memory default needs no import; directoryBackend(root) writes through to a real directory, which is what this run used.

The example got a drive worth reading. The three products’ APIs hold state: tasks, deliveries, hours. What they did not hold is what the site works to: the method statement for the pour, the week’s forecast, building control’s booking rules, and the site diary. Those are documents, and a document belongs on a drive. examples/site/drive/ holds them as every run starts, each run copies them into a scratch directory, and destroyWorkspace empties it at the end. The task list’s note on T-121 stopped repeating the 48-hour rule and points at the file instead.

Each product is told what to read before it speaks, and where to write when it acts. One brief names the documents once. The time tracker reads the pour plan before it says a crew is enough, and the forecast before it says a day holds. The task list reads building control’s rules before it gives a date for the inspection. The materials tracker reads the forecast before it moves a delivery. All three append one line to today’s diary when they change their own state, with bash and >>, so two products writing in one batch cannot overwrite each other. The diary is the one file they all write to, and the host reads it off the disk with /diary.

The goal names the site’s calendar. The runtime stamps the real date into every context, and the scenario is set on Tuesday 25 August. The documents on the drive carry dates, so the second run read every record as a week stale and said so in every summary. One sentence in the goal now says that the products, the drive and the plan keep the site’s calendar, and that the room’s clock is not the site’s date.

Nothing was merged into the tools array, and no assistant reached the drive. Every product keeps its own API and gains the four built-ins beside it. defineHuman refuses an assistant that names a workspace, and the three assistants in this run hold what they held before: one tool, summarise, which reaches the record and nothing else.

Every read of a document lands in a seat’s context, and the pour plan alone is two thousand characters, so a seat that reads before it speaks reads more. The four summaries cost what they cost before, because an assistant reads the record and never the drive. The lock refused sixteen says: three products with more to say raced more often.

The follow-up about Saturday came back as “there is no Saturday plan — the pour date stands at Friday”. The room had settled Friday inside Priya’s first exchange, and the seats answered her from the summaries and their own state. That is the behaviour the last report was built to prove, unchanged with a drive underneath it.

Run on anthropic/claude-sonnet-5, from examples/site. The products, their APIs, the drive they share, the people and their assistants are one shared definition that both this run and the interactive room import. Each product is a defineAgent with its own defineTool API and one workspace field; the drive is a defineWorkspace over directoryBackend; the room is a startSession; each person is a visitSession, and each assistant is the required field on defineHuman. Every activation reached the model and returned; none failed. destroyWorkspace emptied the scratch copy of the drive after the run captured it, and the checked-in seed is as it was.
